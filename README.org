#+TITLE: misemacs
#+OPTIONS: toc:nil num:nil

Reproducible, self-contained [[https://www.gnu.org/software/emacs/][GNU Emacs]] builds for Apple-Silicon macOS — compiled hermetically from a conda-forge toolchain, packaged as a relocatable =Emacs.app=, and installable with [[https://mise.jdx.dev/][mise]] + [[https://packslip.dev/][Packslip]].

misemacs builds Emacs from [[https://github.com/emacsmirror/emacs][=emacsmirror/emacs=]] on a daily cadence that *only publishes when upstream actually changed*. Adding a new Emacs version is a *data change, never a code change*.

* What you get

- *Self-contained =Emacs.app=* — the whole dylib closure (GnuTLS, libxml2, tree-sitter, …) is bundled under =Contents/Frameworks= and its load paths rewritten to resolve from inside the app. No Homebrew, no pixi, no system libraries needed at runtime; it runs on a clean machine.
- *Reproducible* — every C dependency is pinned by a committed =pixi.lock= (the full transitive closure from conda-forge); the pipeline toolchain is pinned by =mise.lock=.
- *GUI (Cocoa/NS) build* with tree-sitter, libxml2, and GnuTLS. JSON is native (no jansson). native-comp is off in v1.
- *Signed CalVer releases* tagged =vYYYY.M.N= in each channel repo (=N= starts at 0 each month and increments for every release), each shipping a signed =packslip.sigstore.json=, =SHASUMS256.txt=, and ad-hoc code signatures.
- *Bundled spell-checking* — [[https://github.com/AbiWord/enchant][enchant]] (with the AppleSpell + Hunspell providers) ships *inside* the app, relocated to resolve from within the bundle, so [[https://github.com/minad/jinx][jinx]] compiles and runs on a clean machine with no Homebrew/system enchant. See *Spell-checking* below.
- On your =PATH= after install: =Emacs=, =emacsclient=, =etags=, =ebrowse=, =emacs-app= (launches the GUI app via =open=, forwarding args), plus =enchant-2= and =enchant-lsmod-2= (the bundled spell-checker CLIs).

*Scope (v1):* macOS =arm64= only, native-comp disabled, ad-hoc signed (not Developer ID / notarized). See the [[docs/superpowers/specs/2026-06-05-bundled-emacs-build-system-design.md][design spec]] §15 for what is designed-for but deferred (native-comp, more arches/OSes, Developer ID, =-nw=).

* Install

Each channel has a GitHub artifact repo that publishes a signed Packslip with every new release. Use a mise version with the Packslip backend, then install the channel you want:

#+begin_src sh
# the most recent master build (swap in -emacs-30 or -emacs-31 for a release branch):
mise use packslip:github.com/djgoku/misemacs-emacs-master@latest

# …or pin a specific signed release (replace the example version with one published):
mise use packslip:github.com/djgoku/misemacs-emacs-master@YYYY.M.N
#+end_src

=Emacs= and friends are then on your mise =PATH=:

#+begin_src sh
mise exec -- Emacs --version
#+end_src

mise verifies the Packslip signer and archive digest. Older releases without a Packslip bundle are not installable through this backend. New releases can be installed by exact version as soon as signing finishes; mise's default 24-hour minimum release age can delay =@latest=.

** Legacy Aqua installs

Existing =emacs-<channel>-YYYY-MM-DD= tags and their assets remain available through the frozen [[registry.yaml][Aqua registry]]. Existing =aqua:= configurations can still reinstall those releases with =MISE_AQUA_REGISTRIES=https://github.com/djgoku/misemacs=. The registry's version prefixes exclude new =vYYYY.M.N= tags, so =@latest= for =aqua:= remains on the last legacy release. Switch to =packslip:= as shown above to receive new releases. Existing local installations are not modified.

** Open it like an app (=open Emacs.app=)

Zero setup: every install (releases after 2026-08-08) puts =emacs-app= on your mise =PATH= — it launches the bundled =Emacs.app= through =open= (LaunchServices: detached, Dock icon, real app semantics) and forwards any args:

#+begin_src sh
emacs-app --init-directory ~/my-emacs-config --debug-init
#+end_src

With args it forces a fresh instance (=open -n=) so they're never silently swallowed by an already-running instance; with no args it focuses/starts the app, like clicking it in Finder.

For Finder, the Dock, and =open -a Emacs= integration: the tarball's top-level dir is the *stable* =misemacs/=, and mise maintains a =latest= symlink per tool — so =…/latest/misemacs/Emacs.app= never moves across upgrades. Link it into =~/Applications= once:

#+begin_src sh
mkdir -p ~/Applications
ln -sfn "$(dirname "$(mise where packslip:github.com/djgoku/misemacs-emacs-master)")/latest/misemacs/Emacs.app" ~/Applications/Emacs.app
#+end_src

Then =open ~/Applications/Emacs.app= (or =open -a Emacs=, Finder, the Dock) launches it like any installed app, and the link survives every =mise up=. Notes:

- The =latest= symlink exists for =@latest= pins (the default above). With a dated pin, link =$(mise where …)/misemacs/Emacs.app= directly and re-link when you bump.
- Spotlight doesn't index symlinked apps — if you want Spotlight to find it, copy instead of link (the app is fully self-contained, so a copy works unchanged).

** Per-channel artifact repos

Each channel publishes its releases to its *own* GitHub repo:

| Packslip tool | artifact repo |
|---------------+---------------|
| =packslip:github.com/djgoku/misemacs-emacs-master= | [[https://github.com/djgoku/misemacs-emacs-master][=djgoku/misemacs-emacs-master=]] |
| =packslip:github.com/djgoku/misemacs-emacs-30= | [[https://github.com/djgoku/misemacs-emacs-30][=djgoku/misemacs-emacs-30=]] |
| =packslip:github.com/djgoku/misemacs-emacs-31= | [[https://github.com/djgoku/misemacs-emacs-31][=djgoku/misemacs-emacs-31=]] |

Each artifact repo signs its own releases using its GitHub Actions identity. This lets mise pin and verify the correct channel repo. =@latest= follows that repo's GitHub Latest marker when eligible; the pipeline moves the marker after signing completes. Without a usable marker, Packslip selects the highest eligible SemVer.

*Fresh-channel caveat.* A newly-added channel has no installable version until its first daily build publishes and its Packslip signing workflow completes.

* Spell-checking (bundled enchant)

Every =Emacs.app= bundles [[https://github.com/AbiWord/enchant][enchant]] under =Contents/Resources/enchant/= as a self-contained, relocated sub-prefix (its own =libenchant=, the Hunspell + AppleSpell providers, and their dylib closure). enchant self-relocates at load time (a =dladdr= constructor), so it resolves entirely from inside the app — no Homebrew, no system enchant.

** jinx (primary)

[[https://github.com/minad/jinx][jinx]] compiles a small C module against =libenchant= on first load. misemacs ships everything that compile needs — headers, a relocatable =enchant-2.pc=, and a scoped =pkg-config= shim — plus a discovery-only =site-start.el= that points jinx's compile at the bundle. So on a clean machine:

#+begin_src sh
# install jinx as usual (ELPA), then enable it — it compiles against the bundled enchant:
emacs --eval "(progn (package-install 'jinx) (global-jinx-mode))"
#+end_src

jinx still needs the *Xcode Command Line Tools* (=cc=) on the user machine to compile its module — that is jinx's own requirement, not something a bundle can remove. "Clean machine" for jinx therefore means "clean except CLT". On an Emacs upgrade the bundled =site-start.el= repairs jinx's embedded library path in place (no recompile). Opt out entirely with =(setq misemacs-enchant-disable t)= or =emacs -Q=.

** ispell.el (bonus)

The =enchant-2= CLI is on your =PATH=, so ispell can use it directly:

#+begin_src elisp
(setq ispell-program-name "enchant-2")
#+end_src

** Backends — AppleSpell default, Hunspell optional (bring your own dictionary)

The default backend is *AppleSpell* (macOS's built-in, multilingual, license-free spell checker); the bundle ships the AppleSpell locale map so =en_US= / =en_GB= / … check and suggest out of the box with *no dictionary files required* (=enchant-lsmod-2= lists the available providers).

The *Hunspell* provider is also bundled, but *no Hunspell dictionaries ship with the app* — Hunspell is bring-your-own. To use Hunspell for, say, =en_US=:

1. Obtain the two dictionary files =en_US.aff= and =en_US.dic= — e.g. from the [[https://github.com/LibreOffice/dictionaries][LibreOffice dictionaries]] repo (=en/=), your distro's =hunspell-en-us= package, or generate them at [[http://app.aspell.net/create][app.aspell.net/create]].
2. Put both files in =~/.config/enchant/hunspell/= (the per-user directory the Hunspell provider searches — no environment variables needed).
3. Tell enchant to prefer Hunspell — add =en_US:hunspell= to =~/.config/enchant/enchant.ordering=.

* How it works

A small *Elixir orchestrator* makes every decision (pure, unit-tested functions), a *bash pipeline* does the heavy lifting, and *mise + pixi* lock every input. GitHub Actions runs it daily behind a cheap change-detection gate, so the expensive macOS build only fires when upstream moved.

#+begin_example
  decide ─▶ build ─▶ finalize
    │         │         │
    │         │         └─ wait for Packslip, merge fragments, flip "Latest"
    │         └─ matrix: one cell per (changed version × target):
    │              build → relocate → package → publish → artifact-repo signing
    └─ change gate: nothing changed ⇒ publish nothing
#+end_example

| Stage      | Owner          | What it does                                                                            |
|------------+----------------+-----------------------------------------------------------------------------------------|
| =decide=   | Elixir         | Resolve upstream SHAs, diff against the last manifest, emit the dynamic build matrix     |
| =build=    | bash + pixi    | =./configure= + =make= a GUI Emacs against the locked per-version pixi env               |
| =relocate= | Elixir         | Bundle the dylib closure, rewrite load paths, ad-hoc sign; gated by an =otool= check     |
| =package=  | bash           | xattr-free tarball + =SHASUMS256.txt= + self-verify                                      |
| =publish=  | bash           | Create the GitHub release (asset + checksums); its artifact repo signs the Packslip   |
| =finalize= | Elixir + bash  | Wait for signed Packslips, merge fragments, attach =build-manifest.json=, flip "Latest" |

The daily workflow ([[.github/workflows/daily.yml][=.github/workflows/daily.yml=]]) runs on a cron, on =workflow_dispatch= (with an optional =force_version=), and on pull requests touching =versions/= or =*.toml= (as a no-publish dry-run).

* Repository layout

#+begin_example
misemacs/
├── versions.toml          # THE manifest: one row per Emacs version (the build list)
├── targets.toml           # OS × arch matrix (v1: macos-arm64 only)
├── versions/
│   ├── master/            # per-version build inputs …
│   │   ├── mise.toml      #   EMACS_REF + configure flags + pixi-env wiring
│   │   ├── pixi.toml      #   conda-forge build deps
│   │   └── pixi.lock      #   full transitive lock (committed)
│   ├── emacs-30/          # … release branches use their compatible locked deps
│   └── emacs-31/
├── orchestrator/          # Elixir brain: pure decision fns + Mix tasks (ExUnit-tested)
├── pipeline/              # bash stages: build-emacs, package, publish, promote
├── scripts/               # configure-check, e2e-packslip-install
├── templates/             # Packslip release workflow installed in each artifact repo
├── mise.toml              # shared task seam (test/lint/build/decide/finalize/…)
└── .github/workflows/     # daily.yml (the automation) + orchestrator-ci.yml
#+end_example

* Adding a build

A "build" is a *version*: one row in =versions.toml= plus a =versions/<name>/= directory holding =mise.toml=, =pixi.toml=, and =pixi.lock=. Adding a new channel also requires a one-time artifact-repo setup — after that, the daily pipeline builds and publishes it automatically.

=emacs-30= is a worked example. The full steps are:

1. Add a row to [[versions.toml][=versions.toml=]] (=ref = "emacs-30"=, =channel = "30"= → its own artifact repo).
2. Add a [[versions/emacs-30/][=versions/emacs-30/=]] directory copied from an existing channel with =EMACS_REF= flipped to =emacs-30=, then resolve and commit its =pixi.lock=. Emacs 30 specifically requires =libtree-sitter >=0.25,<0.26=: it calls =ts_language_version=, which Tree-sitter 0.26 removed.
3. Create the artifact repo and seed it with its generated README (one-time — the README is the required initial commit; without it GitHub returns =HTTP 422 "Repository is empty"= on the first release):
   #+begin_src sh
   gh repo create djgoku/misemacs-emacs-<channel> --public
   mise run artifact-readme -- --version <name> > /tmp/r.org
   gh api repos/djgoku/misemacs-emacs-<channel>/contents/README.org -X PUT \
     -f message="init: artifact repo" -f content="$(base64 -i /tmp/r.org)"
   #+end_src
4. Install [[templates/artifact-packslip.yml][the Packslip workflow template]] as =.github/workflows/packslip.yml= on the artifact repo's default branch. This requires a token allowed to write workflow files. For an artifact repo with no workflow at that path:
   #+begin_src sh
   repo=djgoku/misemacs-emacs-master  # repeat with misemacs-emacs-30 and misemacs-emacs-31
   gh api "repos/$repo/contents/.github/workflows/packslip.yml" -X PUT \
     -f message='ci: sign releases with Packslip' \
     -f content="$(base64 -i templates/artifact-packslip.yml | tr -d '\n')"
   #+end_src
   Do this for the master, 30, and 31 artifact repos before deploying this migration, and regenerate their READMEs with =mise run artifact-readme=. The publisher checks that the installed workflow matches the template before creating a release.
5. Install the publishing GitHub App on the artifact repo so the daily workflow can create releases and trigger its signing workflow.

After step 5, the daily pipeline detects the new version, builds it, and publishes the first signed release to =djgoku/misemacs-emacs-<channel>=. Its exact version is then installable; mise's default release age can delay =@latest=.

The layout contract is enforced by the =version_layout_test= (every =versions.toml= row must have its three input files committed), so a malformed addition fails loudly.

* Development

misemacs uses [[https://mise.jdx.dev/][mise]] as the task runner across local development and CI:

#+begin_src sh
mise run test     # orchestrator ExUnit suite (mix test --warnings-as-errors)
mise run lint     # mix format --check-formatted
mise run fmt      # mix format
#+end_src

Heavier build-related tasks (run =mise tasks= for the full list): =build=, =relocate=, =package=, =publish=, =configure-check=, =cleanroom=, =decide=, =finalize=.

Run =mise run test= and =mise run lint= before pushing. After building, staging enchant, and relocating the app, =mise run cleanroom= checks a launch with the pixi environment moved aside. =mise run e2e -- <owner/repo> <tag>= checks a published Packslip release on a local Mac with fresh mise data and cache directories. Design specs, per-phase plans, and the validation log live under [[docs/superpowers/][=docs/superpowers/=]].
